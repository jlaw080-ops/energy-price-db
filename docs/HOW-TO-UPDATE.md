# 단가 갱신하는 방법

## 공통 순서

```
1. 단가정보/ 에 근거 자료를 넣는다       (파일명: 시행일_종류)
2. data/ 의 JSON을 고친다
3. python3 scripts/validate.py          ← 형식 점검
4. python3 scripts/export_sql.py        ← Supabase용 SQL 다시 만들기
5. Supabase 에 넣고 체크섬 대조          ← 4장
6. 계산 함수 검증 SQL 실행               ← 4장 (전기요금을 고쳤을 때)
7. 커밋 & 푸시                           ← 변경 이력이 남는다
```

## 1. 전기요금이 개정됐을 때

한전은 보통 1년에 2~4회 요금표를 바꿉니다.

1. 한전 홈페이지에서 새 **전기요금표(종합)** PDF를 받습니다.
2. `단가정보/전기요금/종합/YYYY-MM-DD_전기요금표_종합.pdf` 로 이름을 바꿔 넣습니다. (시행일 기준)
3. 직전 연도 JSON을 복사해 `data/electricity/kepco_YYYY-MM-DD.json` 을 만듭니다.
4. 바뀐 숫자를 고칩니다.
5. 아래 두 가지를 **반드시** 돌립니다.

```bash
python3 scripts/validate.py
python3 scripts/verify_electricity.py
```

`verify_electricity.py` 가 "PDF에서 찾지 못한 값"을 알려주면 오타가 난 자리입니다.

> 💡 **요금표 PDF는 글자가 그림으로 박혀 있어서** 자동 추출만으로는 종별 이름을 알 수 없습니다.
> 숫자는 자동으로 뽑되, 어느 표가 어느 종별인지는 사람이 확인해야 합니다.
> Claude Code에게 "새 요금표 PDF 넣었으니 JSON 만들어줘"라고 하면 이 절차대로 처리합니다.

이 4개 시행일은 **주택용만** 주택용 별도 요금표에서 육안 전사해 넣었습니다.
나머지 계약종별(일반용·교육용·산업용·농사용·가로등·심야전력)은 여전히 비어 있고,
한전 홈페이지에서 글자가 살아있는 종합요금표를 다시 받아야 채울 수 있습니다.

### 육안 전사할 때 — 한전 계산 예시로 검산하세요

주택용 요금표에는 한전이 직접 계산한 '요금계산 예시' 가 실려 있습니다.
옮겨 적은 단가로 그 예시를 다시 계산해 보면 전사 오류가 바로 드러납니다.
실제로 이 방법으로 **한전 요금표 자체의 오탈자 3건**을 찾았습니다.

| 요금표 | 틀린 곳 | 인쇄값 | 올바른 값 |
|---|---|---|---|
| 2022-04-01 | ② 전력량요금 | 68,020원 | 70,225원 (내역 합, ⑤도 이 값 사용) |
| 2022-07-01 | ② 전력량요금 | 68,020원 | 70,225원 |
| 2022-07-01 | ⑥ 부가가치세 | 8,310원 | 8,306원 (83,060 × 10%) |

②번만 보고 단가를 역산했다면 틀렸을 것입니다. 항상 **1~3단계 내역**을 기준으로 삼으세요.

2026-04-16·2025-04-01 요금표도 **3페이지(전기자동차 충전전력요금, 분산에너지 부족전력요금)는 미포함**입니다.
3페이지 항목 중 일부는 "무기한 시행 유예 중"으로 표시돼 있어 적용 여부를 확인한 뒤 넣는 게 안전합니다.

### ⚠️ 종별마다 시행일이 다를 수 있습니다

요금표 **주석을 꼭 읽으세요.** 한 장의 종합요금표 안에서도 종별마다 시행일이 다를 수 있습니다.
2026-04-16 요금표가 그렇습니다 — 산업용(을)만 4월 16일 시행이고 나머지는 6월 1일 시행입니다.

이때는 각 종별의 `effective_from` 을 **실제 시행일로** 적어 주세요. 요금표 제목의 날짜를
그대로 복사하면 안 됩니다. `export_sql.py` 가 시행일별로 버전을 나눠 적재합니다.

```json
{ "contract_type": "산업용전력(을)", "effective_from": "2026-04-16", ... }
{ "contract_type": "일반용전력(갑)Ⅰ", "effective_from": "2026-06-01", ... }
```

그리고 `meta.effective_note` 에 주석 내용을 그대로 남겨 두세요. 근거가 됩니다.

하나로 뭉치면 **아직 시행되지 않은 요율로 중간 달이 계산됩니다.** 실제로 그런 버그가 있었고,
`scripts/checksum.py` 와 `export_sql.py` 를 함께 고쳐 시행일별로 나누도록 했습니다.

### ⚠️ 직전 연도 JSON을 복사할 때 반드시 확인할 것

요율 숫자만 보고 복사하면 틀립니다. 실제로 2025-04-01 을 만들 때 아래 두 가지가 달랐습니다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 산업용(을) 봄·가을철 주말 할인 (2026-04-16 신설) | 없음 | 토·일·공휴일 11~14시 50% 할인 |
| 여름철·봄가을철 중간부하 (2026-04-16 변경) | 08~11, 12~13, 18~22시 | 08~15, 21~22시 |
| 여름철·봄가을철 최대부하 (2026-04-16 변경) | 11~12, 13~18시 | 15~21시 |
| **전력산업기반기금** | **3.7% → 3.2% → 2.7%** | 요금표마다 다름 |

마지막 항목은 실제로 틀렸던 것입니다. 최신 연도에서 복사하면서 2.7% 가 따라 들어왔는데,
기금 요율은 세 단계로 인하됐습니다.

| 요금표 | 기금 요율 |
|---|---|
| 2024-04-01 | 3.7% |
| 2024-07-01 · 2024-10-24 · 2025-01-01 | 3.2% |
| 2025-04-01 · 2026-04-16 | 2.7% |

기금 요율은 청구금액에 바로 들어가므로 **매번 1페이지의 `전기요금 × N%` 를 확인**하세요.

그래서 복사한 뒤에는 요율 숫자뿐 아니라 `definitions.time_zones`, `discounts`,
`taxes.power_industry_fund_rate` 를 **해당 연도 요금표에서 다시 확인**해야 합니다.

### 추출기가 조용히 빠뜨리는 경우

일부 요금표는 `116.7` 을 `1`,`1`,`6`,`.`,`7` 처럼 **글자 하나씩 따로** 그립니다.
이런 행은 추출기가 통째로 건너뛰므로, 시간대별 표를 읽을 때는 항상 `--expect` 로
행 수를 지정하세요. 모자라면 오류로 멈춥니다.

```bash
python3 scripts/read_kepco_tables.py <pdf> 2 --tou 305,85,655,700 --expect 27
```

또 2023-05-16 · 2024-01-01 · 2024-04-01 세 요금표는 **텍스트 레이어가 오염**돼 있습니다.
실제 행 위에 조각 글자가 0.3pt 어긋나 겹쳐 `152.4` 가 `52.653.7` 로 망가지고,
심지어 **그 요금표에 없는 옛 값이 유령처럼 남아** 있습니다
(2023-05-16 의 심야전력 자리에서 `71.8 / 50.4` 가 읽히지만, 눈으로 보면 `103.5 / 82.1` 입니다).

이런 요금표는 자동 추출·자동 대조가 불가능하므로 페이지를 이미지로 띄워 눈으로 확인하고,
JSON 의 `meta.skip_pdf_number_check` 에 사유를 적습니다.
그러면 `verify_electricity.py` 가 그 연도를 건너뛰고 사유를 출력합니다.

> ⚠️ **텍스트로 읽힌 숫자를 그대로 믿으면 안 됩니다.** 이 세 요금표에서는
> 보이지 않는 옛 값이 섞여 나옵니다. 반드시 이미지와 대조하세요.

### 기후환경요금 단가는 2021 요금표에만 있습니다

`2021-01-01` 요금표는 **기후환경요금 단가 5.3원/kWh ('21년 1월 기준)** 를 명시합니다.
이후 연도 요금표에는 부과방식만 있고 단가가 없습니다. 그래서 `climate_charge_won_per_kwh` 가
2021 만 값이 있고 나머지는 `null` 입니다. 나머지 연도는 한전 공지에서 채워야 합니다.

### 종별 구성도 바뀝니다

2021-01-01 · 2023-05-16 요금표에서는 **일반용전력(을)과 산업용전력(을)이 한 표**로 묶여
같은 요율을 쓰고 고압C 까지 있습니다. 2024-01-01 요금표부터 두 종별이 갈라지고,
일반용(을)에서 고압C 가 빠집니다. 그래서 이 두 연도만 347행입니다.

2021-01-01 은 **제주 계시별 구조도 다릅니다.** 경·중간·최대부하가 아니라
주말 전체시간 / 평일 기타시간(21~09시) / 평일 수요시간(09~21시) 으로 나뉩니다.
**시간대 구분도 완전히 다릅니다** — 경부하가 23시에 시작합니다(이후 연도는 22시).

요율 숫자만 비교하면 이런 구조 변화를 놓칩니다.

## 2. 가스요금이 개정됐을 때

### 수동 (지금 방식)

1. 공공데이터포털에서 CSV를 받아 `단가정보/가스요금/` 에 넣습니다.
2. `scripts/convert_gas_csv.py` 안의 파일명을 새 파일로 바꿉니다.
3. 실행하면 `data/gas/` 에 JSON이 다시 만들어집니다.

```bash
python3 scripts/convert_gas_csv.py
python3 scripts/validate.py
```

> 원본 CSV가 **EUC-KR 인코딩**이라 그냥 열면 글자가 깨집니다.
> 변환 스크립트가 알아서 처리하므로 직접 고치지 마세요.

### 자동 수집 (API) — ⚠️ 아직 검증 전

`scripts/fetch_odcloud.py` 가 공공데이터포털 API로 최신 자료를 받아옵니다.
**다만 이 스크립트는 아직 실제 호출로 확인하지 못했습니다.** 작성 당시 개발 환경에서
`api.odcloud.kr` 접속이 막혀 있었기 때문입니다.

처음 쓸 때 준비할 것:

1. `.env` 에 `ODCLOUD_SERVICE_KEY_ENC` 를 채웁니다. (공공데이터포털 마이페이지 → 인증키)
2. data.go.kr 의 해당 데이터 페이지에서 **[오픈API] 탭 → 요청주소**를 확인합니다.
   `https://api.odcloud.kr/api/15129722/v1/uddi:abcd-1234` 라면
   `.env` 에 넣을 값은 `15129722/v1/uddi:abcd-1234` 입니다.
3. 먼저 요청 주소만 확인합니다.

```bash
python3 scripts/fetch_odcloud.py --dry-run
python3 scripts/fetch_odcloud.py
```

## 3. 신재생 장비·기타 단가를 추가할 때

`data/renewable-equipment/장비단가_YYYY.json` 의 `items` 배열에 추가합니다.
항목 설명은 [DATA-MODEL.md](DATA-MODEL.md) 3번 참고.

가장 흔한 실수 두 가지:

- **`slug` 를 매번 새로 만드는 것** — 같은 품목이면 `slug` 는 그대로 두고 `base_date` 만 바꿔야 연도별 추이가 쌓입니다.

엑셀로 정리된 단가표가 있으면 그대로 주시면 JSON으로 변환해 드립니다.

## 4. Supabase 에 반영하기

쓰는 프로젝트는 **`jlaw80_DB`** 입니다.
<https://supabase.com/dashboard/project/qhnyrkbmkzhsgthcxoiw>

스키마(`pricing` 스키마와 표 6개)는 이미 적용돼 있고 데이터도 올라가 있습니다.
**단가를 고친 뒤** 아래 순서로 반영하면 됩니다.

```bash
python3 scripts/export_sql.py    # supabase/seed/ 의 SQL 다시 생성
```

1. Supabase 대시보드 → SQL Editor 를 엽니다.
2. `supabase/seed/` 에서 바뀐 데이터의 SQL 파일을 붙여넣고 Run 합니다.
   같은 SQL 을 여러 번 실행해도 중복으로 쌓이지 않습니다(덮어쓰기 방식).
3. 제대로 들어갔는지 대조합니다.

```bash
python3 scripts/checksum.py       # 기대 행수와 체크섬
python3 scripts/checksum.py --sql # 이 SQL 을 SQL Editor 에서 실행
```

두 결과의 **행수와 체크섬이 같으면** 값이 한 칸도 어긋나지 않고 들어간 것입니다.
다르면 그 데이터셋만 다시 넣으세요.

> 💡 SQL 이 너무 길어 한 번에 안 들어가면(특히 전기요금은 320행) 파일을 나눠서 실행해도 됩니다.
> `insert ... values` 한 덩어리를 중간에서 자르지만 않으면 됩니다.

### 수만 행을 한꺼번에 넣어야 할 때 — GitHub 에서 DB 가 직접 읽게 하기

도시가스 소매요금처럼 **수만 행**이면 SQL 을 붙여넣는 방식이 한계에 부딪힙니다.
(소매요금은 67,181행 = 생 SQL 로 5MB 가 넘습니다.)

이때는 **DB 가 GitHub 에서 JSON 을 직접 읽어가게** 하는 편이 훨씬 빠르고 안전합니다.
이 저장소는 공개이므로 `raw.githubusercontent.com` 주소로 바로 받을 수 있습니다.

```sql
-- 1) HTTP 확장을 임시로 켭니다
create extension if not exists http with schema extensions;

-- 2) JSON 을 읽어 그대로 적재합니다 (여러 해를 한 번에 넣어도 됩니다)
with urls(u) as (values
 ('https://raw.githubusercontent.com/jlaw080-ops/energy-price-db/main/data/gas/citygas_%EC%86%8C%EB%A7%A4%EC%9A%94%EA%B8%88_2026.json')),
resp as (select (extensions.http_get(u)).content as body from urls)
insert into pricing.citygas_retail_monthly
       (effective_from, region, use_category, use_detail, won_per_mj)
select (x->>'effective_from')::date, x->>'region', x->>'use_category',
       coalesce(x->>'use_detail',''), (x->>'won_per_mj')::numeric
from resp, jsonb_array_elements((resp.body::jsonb)->'items') as x
on conflict (effective_from,region,use_category,use_detail)
do update set won_per_mj = excluded.won_per_mj;

-- 3) 다 끝나면 확장을 반드시 제거합니다
drop extension if exists http;
```

**주의할 점**

- 파일 이름에 한글이 있으면 주소를 URL 인코딩해야 합니다
  (`소매요금` → `%EC%86%8C%EB%A7%A4%EC%9A%94%EA%B8%88`).
  `python3 -c "import urllib.parse;print(urllib.parse.quote('파일명'))"` 로 변환하세요.
- `http` 확장은 **DB 가 외부로 접속할 수 있게** 만드는 기능입니다.
  적재가 끝나면 바로 `drop extension` 하고, `anon`·`authenticated` 에는
  절대 실행 권한을 주지 마세요.
- 한 번에 3~4개 파일까지가 안전합니다(한 쿼리 안에서 받는 양이 너무 커지면 시간이 초과됩니다).
- 넣은 뒤에는 **반드시 아래 체크섬으로 대조**하세요. 행수만 맞아도 값이 틀릴 수 있습니다.

```sql
select to_char(effective_from,'YYYY') as 연도, count(*) as 행수,
       md5(string_agg(line, E'\n' order by line)) as 체크섬
from (
  select effective_from,
         effective_from::text||'|'||region||'|'||use_category||'|'||use_detail||'|'||
         won_per_mj::float8::text as line
  from pricing.citygas_retail_monthly) cr
group by to_char(effective_from,'YYYY') order by 1;
```

`python3 scripts/checksum.py` 가 내놓는 연도별 값과 **행수·체크섬이 모두 같아야** 합니다.

> 📌 2026-11 적재 기록: 11개 연도 67,181행, 체크섬 11개 모두 일치.

### 긴 SQL 을 쪼개 보낼 때 조심할 것

압축해서 보내려고 `unnest(array[...], array[...])` 처럼 **배열 여러 개를 나란히** 쓸 때,
Postgres 는 길이가 다른 배열을 **짧은 쪽에 NULL 을 채워** 맞춥니다.
그래서 긴 SQL 이 중간에 잘려도 **에러 없이 조용히 일부만 들어갑니다.**

- 배열은 길이가 같은지 보내기 전에 확인하세요.
- 값이 들어가는 칸에는 `not null` 제약을 걸어두세요. 잘리면 적재가 실패해서 바로 알 수 있습니다.
- 그래도 최종 확인은 체크섬입니다.

### 다른 앱에서 REST API 로 읽으려면

`pricing` 스키마는 기본적으로 REST API 에 공개돼 있지 않습니다.
Project Settings → API → **Exposed schemas** 에 `pricing` 을 추가해야
다른 앱에서 `supabase.schema('pricing').from('electricity_rate')` 로 읽을 수 있습니다.

현재 권한은 **읽기는 누구나, 쓰기는 service_role 만** 으로 잡혀 있습니다.
단가는 공개 고시 자료라 읽기를 막을 이유가 없고, 쓰기는 서버에서만 하도록 한 것입니다.
service_role 키는 **브라우저에 노출하면 안 됩니다** (서버·빌드 환경변수로만 사용).

### 요금표를 넣은 뒤에는 계산 함수를 꼭 검증하세요

요율만 맞아도 **반올림 규칙이나 누진 경계가 틀리면 금액이 틀립니다.**
한전이 요금표에 직접 인쇄해 둔 계산 예시와 대조하는 SQL 을 만들어 뒀습니다.

1. SQL Editor 에 `supabase/tests/verify_bill_functions.sql` 을 붙여넣고 Run 합니다.
2. `판정` 칸이 **모두 `일치`** 여야 합니다. 하나라도 `불일치` 면 함수나 요율이 틀린 것입니다.

```sql
-- 검증이 끝나면 이렇게 쓸 수 있습니다
select * from pricing.calc_residential_bill(450, '저압', '2025-07-15');
```

자세한 사용법은 `docs/HOW-TO-QUERY.md` 9절에 있습니다.

함수를 고쳤다면 레포 파일과 DB 가 같은지도 확인하세요.
0006 은 마이그레이션 도구가 아니라 SQL Editor 로 직접 적용하므로
"파일만 고치고 DB 에는 안 올림" 이 생길 수 있습니다.

```bash
python3 scripts/verify_functions_match.py        # 레포 쪽 해시
python3 scripts/verify_functions_match.py --sql  # 이 SQL 을 SQL Editor 에서 실행
```

해시가 다르면 `supabase/migrations/0006_fix_bill_functions_ambiguity.sql` 을
SQL Editor 에 붙여넣고 Run 하면 맞춰집니다. `create or replace` 뿐이라
여러 번 실행해도 안전합니다.

> ⚠️ 기후환경요금·연료비조정단가는 `electricity_tariff_version` 의
> `climate_charge_per_kwh` / `fuel_adjustment_per_kwh` 칸이 아니라
> **`pricing.electricity_surcharge` 표**에서 읽습니다. 분기마다 바뀌는 값이라
> 요금표 버전에 묶어두면 안 되기 때문입니다. 계산 함수도 그쪽을 봅니다.
> 버전 표의 두 칸은 요금표 PDF 에 단가가 적혀 있을 때만 참고용으로 채워둔 것입니다.

> ⚠️ 2021-01-01 요금표에는 **전력산업기반기금율이 적혀 있지 않습니다.**
> 그 시점으로 계산하면 함수가 기금을 0원으로 두고 `주의` 칸에 그 사실을 적습니다.
> 금액을 그대로 쓰지 마세요.

## 5. API 키를 다룰 때 지킬 것

- 키는 `.env` 에만 넣습니다. `.env` 는 `.gitignore` 에 있어 Git에 올라가지 않습니다.
- **채팅창·이슈·커밋 메시지에 키를 붙여넣지 않습니다.** 한 번 올라가면 기록에서 지우기 어렵습니다.
- 실수로 노출했다면 공공데이터포털 마이페이지에서 **인증키를 재발급**하세요.
